# Ситуационный центр: Контейнерные перевозки ЖД

Этот проект осуществляет мониторинг движения контейнерных поездов по
железнодорожным путям РФ, обработку клиентских заявок и выявление
аномалий движения составов.

## Возможности

- **Админ-панель**
  - интерактивная карта (OpenRailMap) с реальной геометрией ЖД-путей;
  - фильтр выбросов (центр масс + множитель среднего расстояния);
  - управление заявками: утверждение / отклонение / привязка к составу;
  - формирование составов, поиск станций через OSM;
  - состав вагонов, фиксация инцидентов.
- **Клиент**
  - отслеживание заказа по трекер-номеру `RZ-YYYY-XXXXXX`;
  - карта с прогрессом, ETA, статусом инцидента;
  - история заявок и подача новой.
- **Симуляция времени**
  - движение вдоль ломаной ЖД-линии с интерполяцией;
  - сдвиг времени, сброс.

## Стек

Python 3.12 · Streamlit · Folium / streamlit-folium · NetworkX ·
SQLite (WAL) · OpenStreetMap (Nominatim / Overpass) · GeoJSON (ODbL).

## Структура проекта

| Файл | Назначение |
|------|------------|
| `app.py` | Точка входа Streamlit: аутентификация, UI, оркестрация |
| `auth.py` | Демо-аутентификация (sha256, роли admin / client) |
| `config.py` | Справочники (`RAIL_HUBS`, `CARGO_TYPES`), таймауты, пути |
| `database.py` | SQLite: схема, CRUD, сид-данные, кэш станций |
| `geo_logic.py` | Чистая математика: центр масс, выбросы, средние расстояния |
| `osm_client.py` | Каскадный поиск станций: кэш → локально → Nominatim → Overpass |
| `routing.py` | Граф ЖД-путей на NetworkX + пространственный индекс, Дейкстра |
| `simulation.py` | Симуляция движения вдоль ломаной (haversine + интерполяция) |
| `ui_components.py` | Переиспользуемые UI-блоки: карты, манифесты, инциденты |

## Запуск

### Windows (рекомендуется)

```bat
:: 1. Распаковать архив railways (data/hotosm_rus_railways_osm_geojson.zip)
setup_data.bat

:: 2. Создать .venv и поставить зависимости
setup.bat

:: 3. Запустить приложение
start_app.bat
```

Приложение будет доступно по адресу: <http://localhost:8501> и откроется автоматически

### Демо-учётки

| Логин  | Пароль | Роль   | Что видит |
|--------|--------|--------|-----------|
| admin  | `a`    | admin  | карту сети, заявки, парк, вагоны, инциденты |
| client | `c`    | client | отслеживание по трекеру, свои заявки |

> Пароли хранятся как sha256-хеш в `auth.py` — это **демо-аутентификация**, не для продакшена.

## Как пользоваться

### Сценарий «Клиент → Админ → Клиент»

1. **Клиент** входит как `client`, вкладка **«Подать заявку на перевозку»** — указывает маршрут, груз, TEU. Получает трекер вида `RZ-2026-A1B2C3`.
2. **Админ** входит как `admin`, вкладка **«Заявки»** — видит ожидающие запросы. Если `find_matching_train` находит подходящий состав по маршруту и свободной ёмкости — кнопка **«Утвердить в состав …»**. Иначе — **«Отклонить заявку»**.
3. **Клиент** снова вводит трекер во вкладке **«Отслеживание груза»** — видит карту, прогресс, ETA и активный инцидент (если есть).

### Сценарий «Создание состава»

Админ → вкладка **«Парк составов»** → форма:

- **Поиск станций (OSM)** — `osm_client.find_station` идёт по каскаду: кэш в SQLite → `RAIL_HUBS` → Nominatim → Overpass.
- **Ручной ввод** — координаты вводятся напрямую (широта 40–80, долгота 19–180).

После нажатия «Сформировать состав»:

1. Проверяется расстояние `haversine_km ≥ 1 км` (иначе «поезду некуда ехать»).
2. `RailGraph.get_rail_route` строит реальный ЖД-маршрут (Дейкстра по графу из GeoJSON).
3. Если путь не найден — fallback на прямую линию с предупреждением.
4. `route_path` (JSON-список `[lat, lon]`) сохраняется в `container_trains`.

### Симуляция времени

Панель под картой (только у админа):

- **Симуляция движения** — вкл/выкл (при выкл. — последняя сохранённая координата);
- **Сдвиг времени, мин** — от −7 до +7 суток;
- **±1 ч** / **Сбросить**.

Функция `simulation.position_at` интерполирует позицию вдоль ломаной `route_path` по пройденному расстоянию `avg_speed_kmh × elapsed`.

## CI/CD

Workflow `.github/workflows/build.yml` (GitHub Actions):

| Job | Что делает |
|-----|-----------|
| **audit** | создаёт временную БД (`init_db`), прогоняет `tools/check_db.py` |
| **build** | `git archive` с учётом `export-ignore` → `dist/railway-sim-<ver>.zip` |
| **release** | на тегах `v*` — прикладывает ZIP к GitHub Release |

### Что попадает в архив

Управляется блоком `export-ignore` в `.gitattributes`. В архив **не** входят:

- Git-служебное: `.git/`, `.github/`, `.gitignore`, `.gitattributes`;
- окружение и кеши: `.venv/`, `venv/`, `__pycache__/`, `*.pyc`, `node_modules/`;
- БД и её WAL: `data/transport.db*`, `*.sqlite`;
- тяжёлые данные: `data/*.geojson`, `data/*.json`, `data/*.zip`, `data/*.gpkg`;
  > справочник станций пользователь получает через `setup_data.bat` (HDX/OSM);
- рабочие файлы: `TODO.txt`, `Project_Files.txt`, `start_copy.bat`,
  `Copy_Files_POSSIBLE_DANGER_RUN_ONLY_HERE.py`.

> Чтобы пустая папка `data/` попала в архив (куда распаковывается справочник),
> добавь `data/.gitkeep` без `export-ignore`.

## Данные и лицензии

- **Источник ЖД-сети:** OpenStreetMap (© OpenStreetMap contributors, ODbL-1.0),
  снимок Geofabrik RUS от 2026-10-17 — 248 912 объектов:
  - 242 471 линия `railway=rail`,
  - 6 393 точки-станции `railway=station`,
  - 48 полигонов.
- **Пакет экспорта:** HOT Export Tool (`oex 0.4.16`), см. `data/README.txt`.
- **Справочник станций** (`data/russia_railway_stations.geojson`) скачивается
  отдельно и **не** входит в репозиторий/релиз.
- **Метаданные:** `data/metadata.json` — STAC-каталог, bbox `(19.87, 41.48, 157.97, 70.33)`.

## Ограничения и известные проблемы

- **Демо-аутентификация:** пароли в открытом виде (sha256) в `auth.py`,
  сессия хранится в `st.session_state`. Не для продакшена.
- **Nominatim / Overpass:** rate-limit и нестабильность. Снижение:
  локальный `RAIL_HUBS`, кэш `station_cache`, таймауты
  (`NOMINATIM_TIMEOUT=6`, `OVERPASS_TIMEOUT=15`).
- **Покрытие OSM:** отражает активность мапперов; в удалённых районах
  данных мало, ЖД-путь может не склеиться → fallback на прямую линию.
- **`find_matching_train`:** сравнивает нормализованную строку маршрута.
  «Владивосток — Москва» ≠ «Владивосток-Москва» без `_norm_route` (уже реализована).
- **`backfill_seed_routes`:** при первом запуске прокладывает `route_path`
  для сидов с `route_path IS NULL`; может занять минуту (кешируется
  `@st.cache_resource`).

## Требования

- **Windows** (скрипты `.bat`) или Linux/macOS с ручной активацией venv;

- интернет — только для `setup_data.bat` и каскадного поиска станций

streamlit-folium>=0.18
